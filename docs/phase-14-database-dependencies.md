# HealthSetu — Phase 14: AI & Intelligence Layer
## Database Dependencies Specification

**Document Version:** 1.0.0  
**Phase:** 14 (AI & Intelligence Layer)  
**Boundary:** Backend application layer contract requirements for the database team.  
**Notice:** Backend does NOT create migrations, alter schemas, or manage DDL. This document defines the exact PostgreSQL entities and fields required by HealthSetu backend services.

---

### 1. Conceptual Architecture & Isolation Boundary

The AI layer operates strictly as an orchestration, summarization, and extraction assistance layer.
- **AI output is NEVER authoritative clinical truth** solely by virtue of being generated by an AI model.
- AI-generated outputs requiring clinical verification must enter existing verification workflows (`REVIEW_REQUIRED`).
- The database schema must preserve complete provenance: the original prompt version, provider, model name, input source references, raw token usage, latency, and clinical review status.

### 2. Required Database Entities

#### 2.1 Table: `ai_tasks`
Tracks asynchronous and synchronous AI task execution requests, states, and parameters.

| Column | Type | Constraints | Description |
|---|---|---|---|
| `id` | VARCHAR(64) | PRIMARY KEY | Unique identifier with prefix (e.g. `aitask-uuid`) |
| `task_type` | VARCHAR(64) | NOT NULL, INDEXED | Approved task type enum (`DOCUMENT_EXTRACTION`, `SBAR_ASSISTANCE`, etc.) |
| `task_version` | VARCHAR(32) | NOT NULL | Version of the task specification (e.g. `1.0.0`) |
| `status` | VARCHAR(32) | NOT NULL, INDEXED | `QUEUED`, `PROCESSING`, `COMPLETED`, `FAILED`, `CANCELLED` |
| `requester_id` | VARCHAR(64) | NOT NULL, INDEXED | User ID who requested the AI task (auditable) |
| `patient_id` | VARCHAR(64) | NULLABLE, INDEXED | Associated patient ID if task is patient-scoped |
| `source_reference_type` | VARCHAR(64) | NULLABLE | Type of input source (`document`, `encounter`, `symptom`, `discharge`) |
| `source_reference_id` | VARCHAR(64) | NULLABLE | Primary key of the source entity |
| `sanitized_input` | JSONB | NOT NULL | Minimized, PHI-filtered input payload passed to AI |
| `provider_name` | VARCHAR(64) | NOT NULL | AI provider invoked (`mock`, `openai`, `azure_openai`) |
| `model_name` | VARCHAR(64) | NOT NULL | Model identifier used (`gpt-4o-mini`, etc.) |
| `prompt_version` | VARCHAR(32) | NOT NULL | Version of the prompt template used |
| `attempts` | INTEGER | NOT NULL DEFAULT 0 | Number of execution attempts |
| `max_retries` | INTEGER | NOT NULL DEFAULT 2 | Max allowed retry count |
| `error_code` | VARCHAR(64) | NULLABLE | Standardized error code if failed |
| `error_message` | TEXT | NULLABLE | Sanitized failure message |
| `created_at` | TIMESTAMPTZ | NOT NULL DEFAULT NOW() | Timestamp task was created |
| `started_at` | TIMESTAMPTZ | NULLABLE | Timestamp execution started |
| `completed_at` | TIMESTAMPTZ | NULLABLE | Timestamp task completed or failed |
| `updated_at` | TIMESTAMPTZ | NOT NULL DEFAULT NOW() | Timestamp record was last updated |

#### 2.2 Table: `ai_results`
Stores validated AI outputs, grounding evaluations, and human review boundaries.

| Column | Type | Constraints | Description |
|---|---|---|---|
| `id` | VARCHAR(64) | PRIMARY KEY | Unique identifier with prefix (e.g. `aires-uuid`) |
| `task_id` | VARCHAR(64) | NOT NULL, FOREIGN KEY (`ai_tasks.id`), INDEXED | Reference to originating AI task |
| `structured_output` | JSONB | NOT NULL | Validated structured JSON output matching task schema |
| `raw_output` | TEXT | NULLABLE | Raw model text before schema parsing (omitted if data retention disabled) |
| `confidence_level` | VARCHAR(32) | NOT NULL DEFAULT 'UNKNOWN' | AI confidence indicator: `HIGH`, `MEDIUM`, `LOW`, `UNKNOWN` |
| `grounding_status` | VARCHAR(32) | NOT NULL | `GROUNDED`, `PARTIALLY_GROUNDED`, `UNGROUNDED`, `SKIPPED` |
| `grounding_notes` | JSONB | NOT NULL DEFAULT '[]' | Field-level grounding evaluation details |
| `source_citations` | JSONB | NOT NULL DEFAULT '[]' | Source evidence citations (`document_id`, `page`, `span`, `text`) |
| `uncertainties` | JSONB | NOT NULL DEFAULT '[]' | Model-reported or validator-identified ambiguities |
| `missing_information` | JSONB | NOT NULL DEFAULT '[]' | Required clinical attributes absent from input |
| `verification_status` | VARCHAR(32) | NOT NULL, INDEXED | `REVIEW_REQUIRED`, `VERIFIED`, `REJECTED`, `NOT_APPLICABLE` |
| `verified_by` | VARCHAR(64) | NULLABLE, INDEXED | Clinician user ID who verified/corrected this result |
| `verified_at` | TIMESTAMPTZ | NULLABLE | Timestamp of human clinical review |
| `verification_notes` | TEXT | NULLABLE | Clinician notes or correction summary |
| `created_at` | TIMESTAMPTZ | NOT NULL DEFAULT NOW() | Timestamp result was recorded |
| `updated_at` | TIMESTAMPTZ | NOT NULL DEFAULT NOW() | Timestamp result was updated |

---

#### 2.3 Table: `ai_usage_records`
Captures operational token usage, latency, and cost estimates without exposing PHI.

| Column | Type | Constraints | Description |
|---|---|---|---|
| `id` | VARCHAR(64) | PRIMARY KEY | Unique identifier (`aiuse-uuid`) |
| `task_id` | VARCHAR(64) | NOT NULL, FOREIGN KEY (`ai_tasks.id`), INDEXED | Reference to AI task |
| `provider_name` | VARCHAR(64) | NOT NULL | Name of provider (`mock`, `openai`) |
| `model_name` | VARCHAR(64) | NOT NULL | Name of model |
| `input_tokens` | INTEGER | NOT NULL DEFAULT 0 | Prompt token count |
| `output_tokens` | INTEGER | NOT NULL DEFAULT 0 | Generated completion token count |
| `total_tokens` | INTEGER | NOT NULL DEFAULT 0 | Total token consumption |
| `latency_ms` | INTEGER | NOT NULL DEFAULT 0 | End-to-end provider execution latency in ms |
| `estimated_cost_usd` | NUMERIC(10, 6) | NULLABLE | Estimated cost in USD based on model pricing |
| `status` | VARCHAR(32) | NOT NULL | `SUCCESS`, `ERROR`, `TIMEOUT`, `RATE_LIMITED` |
| `request_id` | VARCHAR(64) | NULLABLE, INDEXED | Distributed correlation request ID |
| `created_at` | TIMESTAMPTZ | NOT NULL DEFAULT NOW() | Timestamp recorded |

### 4. Integrity and Non-Functional Requirements
1. **Deny-by-default on Verification:** Initial state for clinical outputs must be `REVIEW_REQUIRED`. AI cannot set `VERIFIED`.
2. **Audit & Provenance:** Foreign keys link task -> result -> usage for non-repudiable audit trails.
3. **No PHI in Usage Logs:** `ai_usage_records` must NOT store raw text, prompts, or patient clinical identifiers.
4. **Idempotency:** Re-running a task creates a new record or increments `attempts`, preserving audit history.
